### Harness: gam

**Overview**: GAM couples Flash-Searcher-style DAG planning with Generative Agent Memory (GAM) in a ReAct loop. A planner decomposes the task into parallel goals with fallback paths; a tool-calling loop then executes JSON steps (think plus up to 5 tool calls) until final_answer or max steps. Every step is abstracted into memory pages that periodic research passes reorganize into an integrated summary replacing raw history, suiting long multi-step tool tasks.

**Component implementations**:
- **memory.py — `GAMMemory`**: Each step becomes a one-paragraph LLM abstract (fallback: first 200 chars) plus a page embedded via all-MiniLM-L6-v2 into FAISS; plans/summaries are memorized too. Every 4 steps a plan-search-integrate-reflect research pass (max 3 iterations) issues an LLM JSON search plan over BM25 keyword, FAISS vector, and page-index channels (top-5 hits, 500-char snippets), LLM-integrates hits, and reflects (sufficiency check, up to 5 follow-ups) to decide iteration. Context = system prompt + task + integrated memory (abstracts before first research) + last 3 raw steps.
- **planning.py — `FlashDAGPlanning`**: Initially the LLM (tool schemas truncated to 2000 chars) emits 1-5 independent goals, each with 1-5 sequential fallback paths and success criteria, as plain text. Every 8 steps it replans: goals are marked completed/in-progress/blocked with recommended next parallel sub-paths; the summary overwrites the plan as the new directive.
- **action.py — `ReActAction`**: Owns the loop: step 0 plans; each iteration optionally replans, rebuilds memory context, renders a Jinja step prompt (tool schemas + task), and calls the model; failures become error steps. json_repair parses output into think plus tool calls; per-tool exceptions become error observations; final_answer ends the run. At max steps a forced final-answer LLM call is appended.
- **tool_policy.py — `AllToolsPolicy`**: Exposes the full catalog unfiltered every step as JSON schemas (any-to-string coercion, non-nullable params required); a skills registry loads only when enabled, adding a skills prompt; final_answer is handled by the action loop.
- **prompt.yaml**: `system_prompt` sets the execution policy (parallel goals, one path per goal, JSON think/tools output, tools/skills injected via Jinja). `planning.initial_plan` and two `summary` templates serve the planner; five `memory` prompts serve GAM (abstraction, retrieval planning, integration, sufficiency check, follow-ups). `step.pre_messages` governs each action step (1-5 tool calls, no near-duplicates, task-language answers); `final_answer.pre/post_messages` drive the forced answer.
