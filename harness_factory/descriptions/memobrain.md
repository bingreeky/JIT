### Harness: memobrain

**Overview**: MemoBrain is a marker-based ReAct agent whose distinguishing mechanism is a dependency-aware reasoning-graph memory (adapted from the MemoBrain project). The agent loops: passive recall check, one LLM call over the raw chat history, then marker parsing — a tool-call tag executes a tool and passively patches the graph via a memorize LLM call, an answer tag (or the final_answer tool) terminates, and no marker falls through to the next turn. Memory reshaping is entirely passive, driven by loop position and a token budget rather than agent decisions. It suits long-horizon research/tool-use tasks where context would otherwise overflow.

**Component implementations**:
- **memory.py — `MemoBrain reasoning-graph memory`**: Maintains two synchronized states: an OpenAI-style message list (what the LLM sees) and a ReasoningGraph of task/subtask/evidence/summary nodes linked by rationale-bearing edges, each node tracking the message indices it covers. After every completed tool call, `memorize_pair` appends the tool response and has an LLM emit a JSON patch adding subtask/evidence nodes and edges. At the start of each turn, if the message list exceeds 32K tokens (tiktoken o200k_base), recall fires: an LLM picks redundant nodes to flush and sequential paths to fold into summary nodes, then the message list is rebuilt from the graph — the first 3 and last 4 messages are always protected. Auxiliary LLM calls get 3 retries with 3-second backoff and markdown-fence stripping; parse failures are logged and skipped leniently.
- **planning.py — `NoPlanning`**: A deliberate no-op. The initial plan is the fixed string "No explicit plan," replanning is never triggered, and the directive is just the task text; all reasoning is driven by the system prompt plus accumulated messages.
- **action.py — `MemoBrain marker-based ReAct loop`**: A while-loop bounded by min(runtime max_steps, 200 LLM calls). Each turn: passive recall check, LLM call with stop sequences on the tool-response tag (hallucinated tails are truncated), then marker parsing — tool-call JSON is repaired via json_repair, malformed calls return an error observation, tool exceptions become observations, and successful calls trigger memorize. If no marker appears and context exceeds 105K tokens, a one-shot force-answer prompt is injected (not persisted to memory); if the loop exits without an answer, a fallback prompt over accumulated memory forces one.
- **tool_policy.py — `Flat tool policy`**: Flat policy — the full catalog is exposed every step with no retrieval or filtering, formatted as JSON schemas (nullable inputs optional). Optionally loads a skills prompt. The final_answer tool is treated by Action as equivalent to the answer marker and terminates immediately.
- **prompt.yaml**: `system_prompt` (Action/Memory) instructs stepwise reasoning, tool calls via tool_call tags, and finishing via final_answer, with Jinja-rendered tool schemas and a date placeholder. `memory.memorize_sys_prompt` and `memory.flush_fold_sys_prompt` (Memory) drive graph patching and flush/fold selection, both demanding strict JSON. `force_answer.limit_message` and `final_answer.pre/post_messages` (Action) handle the two forced-termination paths; planning/summary keys are fixed no-op strings.
